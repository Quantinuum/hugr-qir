# Result Recording

This page collects caveats for recording and retrieving results when submitting QIR generated by `hugr-qir` to H-Series systems through Nexus.

## Supported Result Types

`hugr-qir` currently supports recording only integer and boolean values through Guppy's `output` function. Other output value types are not part of the supported H-Series QIR subset.

For example, a program can record a measurement bit directly:

```python
output("q0", measure(q).read())
```

or record an integer that packs several boolean results:

```python
integer_value = (integer_value << 1) | int(bit)
output("random_int", integer_value)
```

Packing multiple boolean values into an integer is often easier to interpret after retrieval than reading each boolean tag independently.

## Nexus Result Shape

When results are retrieved through Nexus, the `BackendResult` reports all tagged results as 64-bit integers. This applies even when the original Guppy result was recorded as a boolean. In that case, the boolean value is represented by the last bit of the 64-bit value, with the preceding bits expected to be zero.

This raw shape is useful for preserving the backend result exactly, but it is not always the most convenient form for user-facing analysis. The helper described below exposes those values as bitstrings, integers, or boolean-oriented representations.

## Result Helper

The `BackendResult` object returned by Nexus can be passed into `HugrQirResultHelper` for easier handling:

```python
from hugr_qir.h_series_helpers.results import HugrQirResultHelper

hqr_result = HugrQirResultHelper(backend_result)
```

By default, `get_shots()` returns the same full 64-bit bitstring representation as `get_shots_all_bitstring()`:

```python
shots = hqr_result.get_shots()
```

For all tags, the helper also provides direct 64-bit bitstring and integer views:

```python
bitstrings = hqr_result.get_shots_all_bitstring()
integers = hqr_result.get_shots_all_integer()
```

Each of these methods returns one dictionary per shot, keyed by result tag.

## Configuring Representations

Users can provide a `ResultRepresentationSpec` containing a dictionary that maps specific result tags to a `ResultRepresentation`. Tags omitted from this dictionary use the fallback representation passed to `get_shots()`, which defaults to `ResultRepresentation.BITSTRING`.

```python
from hugr_qir.h_series_helpers.results import (
    HugrQirResultHelper,
    ResultRepresentation,
    ResultRepresentationSpec,
)

result_representations = {
    "q0": ResultRepresentation.BOOL_BITSTRING,
    "q1": ResultRepresentation.BOOL_BITSTRING,
    "random_int": ResultRepresentation.INT,
}

hqr_result = HugrQirResultHelper(
    backend_result,
    ResultRepresentationSpec(result_representations),
)

shots = hqr_result.get_shots()
```

The available representations are:

| Representation | Output shape | Notes |
|----------------|--------------|-------|
| `ResultRepresentation.BITSTRING` | Full 64-bit string | Default fallback |
| `ResultRepresentation.INT` | Python `int` | Interprets the 64-bit bitstring as a base-2 integer |
| `ResultRepresentation.BOOL` | Python `bool` | Only valid when all bits except the last bit are zero |
| `ResultRepresentation.BOOL_BITSTRING` | `"0"` or `"1"` | Only valid when all bits except the last bit are zero |

Boolean representations are validated when `HugrQirResultHelper` is constructed for explicitly configured tags. If `get_shots(default_representation=...)` uses a boolean representation as a fallback, any non-boolean-shaped fallback tag raises an error when shots are requested.
